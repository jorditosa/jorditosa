## 📐 Spec-Driven Development (SDD)

I build software **spec-first**: the specification is the source of truth and the code is its implementation. Combining this approach with AI agents such as **Claude** keeps intent, tests and implementation aligned from the very first commit.

**Spec-First** — the spec comes before the code:

1. Capture the intent: goals, scope, constraints and acceptance criteria.
2. Turn the spec into a technical plan: architecture, contracts and data models.
3. Break that plan down into small, independently verifiable tasks.
4. Implement each task and validate it against its acceptance criteria.

**Spec-Anchored** — the spec stays alive once the code exists:

- The spec lives in the repository, versioned and reviewed like any other artifact.
- Every change starts with a spec update, and the implementation follows from it.
- Tests (Playwright, Jest) are derived from the spec, so drift is caught early.
- Security requirements (OWASP, threat modelling) are part of the spec, not an afterthought.

Why it pays off: less rework, decisions that can be reviewed, reproducible AI-assisted workflows and documentation that never goes stale.
